# Откат РаскройPro — «кнопка назад»

Если после обновления что-то сломалось у пользователей — по порядку, от самого быстрого.

## 1. Мгновенно, за минуту, без кода — откат в Vercel
1. Открыть https://vercel.com/dashboard → проект **cutting-app** → вкладка **Deployments**.
2. Найти последнюю рабочую версию (Production, до неудачного обновления).
3. Справа «⋯» → **Instant Rollback** (или **Promote to Production**) → подтвердить.

Сайт сразу возвращается к той версии. Код в GitHub не меняется — потом спокойно исправляем и выкладываем снова
(после нового пуша Vercel опять опубликует свежую версию).

## 2. Выключатели функций — без отката
Новые крупные функции делаются с выключателем у мастер-аккаунта:
- **Пробный вход без регистрации** — «Пользователи» → «Пробный режим без регистрации» → «Выключить».
  Кнопка «Попробовать без регистрации» пропадает с экрана входа.

## 3. Откат кода к сохранённой стабильной версии
Перед каждым большим изменением сохраняется ветка `stable-ГГГГ-ММ-ДД` (точная копия рабочей версии):
- `stable-2026-11-15` — перед пробным режимом без регистрации.

Написать Claude: «откати приложение на stable-2026-11-15» — он вернёт код этой ветки в main и выложит.
Вручную: `git checkout stable-2026-11-15 -- . && git commit -m "Откат на stable-2026-11-15" && git push`.

## База данных (Supabase)
Миграции только добавляют (новые колонки, функции `create or replace`) и ничего не удаляют — откат кода
их отката не требует: старая версия приложения с новой базой работает.

## Правило для разработки
- Перед большим изменением — ветка `stable-<дата>` с текущего main и строка в этом файле.
- Новое, что меняет поведение для всех, — за выключателем (мастер-аккаунт или настройка производства).
