# РаскройPro — Контекст проекта

## Суть проекта
Веб-приложение (PWA) для автоматизации раскроя листового материала (ЛДСП).
Клиенты вводят детали с телефона, получают карты раскроя, оформляют заказ.
Производство видит заказы, меняет статусы, печатает бирки и УП для ЧПУ.

## Технологии
- **Frontend**: React + Vite (PWA)
- **Backend/DB**: Supabase (PostgreSQL + Auth + RLS)
- **Хостинг**: Vercel (автодеплой из GitHub)
- **Репозиторий**: https://github.com/Nurzhan-Tlegenov/cutting-app
- **Prod URL**: https://cutting-app-nine.vercel.app
- **Supabase**: https://bmcmyrdsxievaglpspcn.supabase.co

## Стандарт координат (мебельный)
- Лист: **2750×1830** — первое число Y (вертикаль), второе X (горизонталь)
- Деталь: **Длина×Ширина** — Длина=Y (вертикаль), Ширина=X (горизонталь)
- Пример: деталь 700×400 → 700 по Y (высокая), 400 по X (узкая)
- Текстура идёт вдоль Y (первого числа)

## SQL для новой установки
```sql
-- Профили
create table if not exists profiles (
  id uuid references auth.users(id) primary key,
  created_at timestamp default now(),
  email text, full_name text, phone text, whatsapp text,
  role text default 'client'
);
alter table profiles enable row level security;
create policy "profiles full access" on profiles for all using (true);

-- Заказы
create table if not exists orders (
  id uuid default gen_random_uuid() primary key,
  created_at timestamp default now(),
  user_id uuid references auth.users(id),
  order_number text, order_name text, material_name text default '',
  sheet_length numeric default 2750, sheet_width numeric default 1830,
  margin_top numeric default 10, margin_right numeric default 10,
  margin_bottom numeric default 10, margin_left numeric default 10,
  kerf_width numeric default 4,
  status text default 'draft',
  nesting_result text
);
alter table orders disable row level security;

-- Детали
create table if not exists order_details (
  id uuid default gen_random_uuid() primary key,
  created_at timestamp default now(),
  order_id uuid references orders(id) on delete cascade,
  prefix text, name text, display_name text,
  length numeric, width numeric, qty integer default 1,
  edge_top text, edge_right text, edge_bottom text, edge_left text,
  rotatable boolean default true, sort_order integer default 0,
  contour text
);
alter table order_details disable row level security;
```

## Редактор контура (ContourEditor.jsx) — ключевая архитектура

### Координатная система
- 0,0 = нижний левый угол детали, Y вверх
- Canvas инвертирует Y: `canvasY = oy + dh - v.y * sc`

### Типы вершин
- `'point'` — обычная точка (r=0 острый, r>0 скругление arcTo)
- `'arc'` — контрольная точка дуги через 3+ точек
- `'fillet'` — явная дуга скругления (fcx, fcy, fr, fa0, fa1, fccw)

### Слои контура (для G-кода)
- **Detal** — внешний контур детали
- **Vyrez** — сквозные вырезы (прямоугольник, круг)
- **Paz(глубина)** — пазы с глубиной (например Paz(6), Paz(8))

### Вырезы (holes)
- Прямоугольный вырез хранит `vertices` — 4 точки (конвертируются через `holeToVertices()`)
- При изменении размеров/привязки — vertices пересчитываются (если не `_verticesEdited`)
- Можно редактировать точки выреза как внешний контур
- `activeHoleIdx` переключает контекст редактирования

### Радиус скругления
- На стыке двух прямых: `r` на вершине → `buildPath` использует arcTo
- На стыке прямой и дуги: создаются точки tp, fillet, ta через `findFillet()`
- `findFillet()` — геометрически точный центр скругления
- Превью при вводе R показывается через `previewVerts`
- Кнопка «Выбрать другой отрезок» переключает `fccw` у fillet точки

### Дуга через точки
- Выбор точек через кнопки слева + тап по canvas
- 3+ точек → кнопка «Применить дугу»
- Средние точки помечаются `type:'arc'`
- Рисуется через circumcircle formula

## Алгоритм нестинга (src/lib/nesting.js)
- Алгоритм: Maximal Rectangles Best Short Side Fit (BSSF)
- Вращение только если `rotatable=true`
- Результат сохраняется в `orders.nesting_result` как JSON

## Визуализация раскроя (NestingPage)
- Canvas: масштаб по ширине листа
- Двойной тап = поворот детали
- Одиночный тап+drag = перемещение с магнитом 50мм
- Запрет пересечений при перетаскивании

## Импорт из «Астра Конструктор Мебели» (.add)

- В импорте деталей четвёртый источник — «Астра». Файл `.add` читается прямо в браузере: `src/lib/cfb.js` (достаёт поток `Contents` из составного файла OLE2) и `src/lib/astraAdd.js` (`parseAstra`, `readAstraFile`). Формат восстановлен по одному файлу (версия 320) и описан в шапке `astraAdd.js`: это архив MFC без подписей полей, поэтому каждый класс разбирается своим обработчиком (`H`). Незнакомый класс или другая раскладка — понятная ошибка «эта версия файла Астры пока не читается».
- Общая часть с Базисом: `basisB3d.js` теперь отдаёт `buildItem(src, holes, faceRule)` (нейтральное описание панели -> деталь заказа) и `groupItems`. Базис и Астра готовят `src` каждый по-своему, дальше всё одинаково: контур, вырезы, кромка (в т. ч. на фигурных участках), пазы, выбор лицевой стороны, `contour.meta` (у Астры `meta.src = 'astra'`, обозначение — как в её чертежах: `позиция(изделие)`, напр. `9(P1)`).
- Присадка. Отверстий в файле нет: на торцах деталей стоит крепёж (расстояние от начала/конца стороны + тип). Отверстия строим по параметрам крепежа — в торце своей детали и в пласти той, к которой торец прилегает (ищется геометрически, как у Базиса). Поддержаны: шкант, конфирмат/саморез/соединитель, минификс (шток + эксцентрик), полкодержатель и стяжка, петли (чашка + отверстия ответной планки на боковине), просто отверстия от фурнитуры ящиков.
- Проверка: сверено с XML-экспортом самой Астры (Файл → Экспорт XML) по четырём проектам (тумба, 5180, 5182, 5079 — всего 463 детали). Совпадают: число деталей, размеры, толщина, материал, кромка по сторонам, флаг «можно вращать», пазы, вырезы, фигурные контуры; отверстия в пласти — 3742 из 3772, в торцах — 1632 из 1648. Известные расхождения: (1) у деталей с угловой вырубкой XML считает торцевые отверстия от края габарита, мы — от конца прямого участка (ответные отверстия в пласти при этом совпадают, значит верно у нас); (2) «Присадка» толщиной 1 мм (шаблон сверления алюминиевой рамки) — у нас глубина обрезается толщиной детали; (3) ответная планка «терминальной» петли (4 отв. в 5079) пока не ставится.
- 3D: все панели и остальные тела (техника, профили, ящики, стены) — как тела выдавливания; цвета материалов берутся из файла (`scene.colors`). Анимации дверей и ящиков в файле Астры нет.
- Материал `FREE` в Астре — «не назначен» (вспомогательные плоскости под перфорацию): в списке он отдельной группой, в общий 3D-вид не попадает.
- Одинаковые детали с одним номером позиции в одном изделии складываются в одну строку с количеством (как в XML Астры); с разными номерами — отдельными строками.
- Покупные изделия сеткой (CPartArt: ножки и т. п.) идут в 3D как фурнитура (`scene.meshes`).
- «Можно вращать на раскрое» берётся из детали (поле перед CAngled): 1 — есть направление текстуры.

## Несколько материалов в заказе, XML Астры, подсветка двусторонних

- **Материал при раскрое.** Если в заказ импортирована модель целиком («Все вместе»), у деталей разные листовые материалы (`contour.meta.material` + `thickness`; у деталей без них — материал заказа). `src/lib/detailMaterial.js`: `detailMatKey`, `materialsOf`. На странице раскроя появляется выпадающий список «Материал»; кроится один материал за раз. Сохранённый раскрой при нескольких материалах лежит в `orders.nesting_result` как `{ multi: true, byMat: { 'материал|толщина': результат } }` (при одном материале — как раньше, сам результат). В списке галочкой отмечены материалы с выбранным раскроем; при оформлении заказа предупреждаем, если какой-то материал ещё не раскроен. Параметры листа пока общие на заказ — перед раскроем другого материала их можно поменять, в результат они записываются.
- **XML-экспорт Астры** (`src/lib/astraXml.js`, Файл → Экспорт XML в Астре) — запасной путь, если `.add` не читается: детали, количество, кромка, контур, вырезы, пазы, присадка в пласть и торцы; 3D нет (в XML нет положения деталей). Сверено с импортом из `.add` на четырёх проектах: 446 деталей из 463 совпадают полностью, остальные — известные особенности XML (торцевые отверстия у угловых вырубок, паз через П-образный вырез). У торцевых отверстий на длинных сторонах в XML не всегда видно, от какого конца они отсчитаны — такие детали помечаются предупреждением при импорте.
- **Двусторонняя обработка на карте раскроя** — полупрозрачный фиолетовый фон детали (вместо пунктирной рамки); отверстия с изнанки по-прежнему пустыми кружками.

## 3D-просмотр: прозрачность, кромка, скрытие материалов; фильтр материала в списках; карта раскроя

- **3D.** В «Полупрозрачном» — ползунок прозрачности. В «Каркасе» — подсветка торцов с кромкой: галочка, цвет и прозрачность (ленты по контуру на всю толщину; `model3d.js` отдаёт `bands` — ломаные участков с кромкой: стороны, фигурные участки, вырезы). Панель «Материалы»: галочка у материала показывает/скрывает все его детали (вместе с отверстиями, пазами и линиями), там же — картинки декора. Настройки вида (`view3d`: прозрачность, цвет и прозрачность кромки) идут за аккаунтом; скрытые материалы — только на время просмотра. В сохранённую сцену (`scene.parts`) теперь пишется и кромка по сторонам — у моделей, импортированных раньше, кромка подсветится только у деталей самого заказа.
- **Фильтр материала в списках.** `MaterialFilter` — выпадающий список «Все материалы / материал · толщина — шт.» в бланке заказа (новый и редактирование) и в самом заказе; появляется, когда в заказе несколько листовых материалов. Фильтрует только показ списка, детали не удаляет.
- **Карта раскроя.** Галочка «Кромка» рядом с выбором подписи скрывает линии кромки (за аккаунтом, `nestShowEdges`). Отверстия в торец рисуются полосой на всю глубину и шириной в диаметр (`getAllDrillPoints` отдаёт для них `edge, dx, dy, depth`).

## 3D: настройки каркаса, подсветка стороны присадки; на карте — только лицевая присадка

- **Настройки вида в 3D — выпадающая панель** (кнопка ⚙ в строке режимов, открывается поверх модели, чтобы не занимать экран телефона): прозрачность «Полупрозрачного», цвет / толщина / прозрачность линий каркаса, подсветка кромки. Линии — «толстые» (`LineSegments2` + `LineMaterial`), толщина в пикселях. В `view3d` добавлены `wireColor`, `wireW`, `wireOp`.
- **Подсветка стороны присадки** — там же две взаимоисключающие галочки: «Подсветить лицевую» (зелёный) и «нелицевую» (фиолетовый). `model3d.js` отдаёт у отверстий в пласть `side: 'front' | 'back'`. Нужна в первую очередь в «3D-вид детали» редактора контура — видно, где сейчас лицевая присадка.
- **Карта раскроя** показывает только присадку лицевой стороны (`getAllDrillPoints(..., frontOnly = true)`); отверстия с изнанки в детали остаются, фиолетовый фон детали напоминает о них. После «Перевернуть деталь» в редакторе стороны меняются местами — на карте появляются бывшие нелицевые.
- **Пазы на карте раскроя.** Раньше не рисовались вовсе. Теперь пазы лицевой стороны — оранжевые прямоугольники в масштабе (`getGrooveRects` в `drillGeometry.js`, поворачиваются вместе с деталью); пазы с изнанки, как и присадка, появляются после переворота детали. В общем обзоре «Все листы» (мелкие схемы) пазов и присадки нет — только на карте отдельного листа.

## Импорт из PRO100 (OBJ)

- Файл проекта `.sto` зашифрован и не читается. Рабочий путь — модель, сохранённая из PRO100 в OBJ (`src/lib/pro100Obj.js`: `parsePro100Obj`, `readPro100Obj`); в импорте это источник «PRO100», файл `.obj`.
- В OBJ есть только геометрия. Панель = объект-брусок (три взаимно перпендикулярных направления граней, все вершины в углах) толщиной 2.5–60 мм; берём длину (большая сторона, поворот на листе запрещён), ширину, толщину и положение в модели (3D работает). Единицы — метры или мм (определяется по габариту). Остальные объекты идут в сцену как «фурнитура» (сетка).
- Названий, материала, кромки, присадки в файле нет: название подставляется по положению (высота — ось Y: «Полка» / «Стойка» / «Планка»), материал пустой (берётся материал заказа, группа по толщине), одинаковые размеры объединяются в строку с количеством. Результат помечен `bare: true` — в окне импорта вместо настроек присадки показывается пояснение.
- Проверено на одном файле (кухня, 154 панели 16 мм → 60 строк). Следующий шаг по словам заказчика — он скажет, как с этим работать дальше (возможна склейка с отчётом PRO100 по размерам).

## Поворот детали на листе: одно поле `rotation`

- Причина рассинхрона присадки/пазов с деталью (детали с отключённой текстурой): прямоугольный раскрой поворачивал деталь в двух местах — заранее (`rotatePiece` при «вдоль X/Y») и при укладке (`rot`, `flip`), а наружу отдавал только флаг `rotated` последнего шага. Кромка поворачивалась на каждом шаге и была верной, а присадка и пазы на карте считались по `rotated` — отсюда 90°/180° расхождения.
- Теперь `nesting.js` ведёт полный поворот: у заготовки `rot0` (градусы), у уложенной детали `rotation` = 0/90/180/270 от исходной. Все потребители берут его через `placedTurns(p, detail)` (`partHoles.js`) / `placedRotation` (`trueShapeNesting.js`); у старых сохранённых раскроев поля нет — там поворот определяется по габариту (0/90), поэтому их лучше пересчитать. `roughShapePolygons` отдаёт контур во всех четырёх положениях.
- Проверка: для всех уложенных деталей (фрезер/пила × авто/вдоль X/вдоль Y) габарит и кромка совпадают с поворотом исходной детали на `rotation`.

## DXF раскроя: всё, что на карте, по слоям

- `dxfExport.js` выгружает то же, что рисует карта листа, каждый тип на своём слое: `sheet` (лист), `detal` (контур детали), `vyrez` (вырезы), `PAZ_W<ширина>_Z<глубина>` (пазы, прямоугольник), `D<диаметр>_Z<глубина>` (отверстия в пласть, CIRCLE), `TOREC_D<диаметр>_Z<глубина>` (отверстия в торец — прямоугольник «диаметр × глубина» от кромки), `kromka` (кромка, линия с отступом 3 мм внутрь; на фигурных участках — по контуру), `Solid Edge 2D NestingPartName` (подпись детали), `label` (подпись листа).
- Только лицевая сторона — как на карте. Глубина сквозного отверстия = толщина материала.
- В файле есть таблица слоёв (TABLES/LAYER, у типов свои цвета), слои идут по порядку: лист → деталь → вырезы → пазы → отверстия (по диаметру и глубине) → торцевые → кромка → подписи; объекты в ENTITIES сгруппированы в том же порядке.
- `getAllDrillPoints` теперь отдаёт у каждого отверстия свои `d` и `depth` (у парных и дополнительных — собственные), `getGrooveRects` — `width`, `depth`.

## 3D-просмотр: подписи, изоляция, виды, взрыв-схема, правка кромки и присадки, ссылка для клиента

- **Имя штуки (pid).** `model3d.js` даёт каждой штуке модели постоянное имя (`makePidGen`: файл + ID панели, иначе строка/номер). По pid 3D помнит, что потушено и выбрано, даже когда строки заказа делятся и склеиваются. Все объекты сцены (панель, линии, кромка, пазы, отверстия, подпись) помечены `__pid`.
- **Подписи на деталях** — список «Подписи: нет / позиция / обозначение / наименование» в строке инструментов (`view3d.label`, идёт за аккаунтом). Позиция — `meta.pos`, а если её нет (OBJ) — номер строки заказа.
- **Долгое нажатие на деталь** → меню: оставить только деталь / блок (Базис, Астра: `meta.product` + `meta.path`) / корпус / выбранные, «Выбрать несколько деталей…» (тапами), скрыть, «Править деталь». «Корпус» считается сам — группы деталей, связанных стыками (`partGroups`); большие детали-связки (столешница, цоколь) в корпус не входят. Вверху — «Показано N из M · показать всё».
- **Виды** — спереди / сзади / слева / справа / сверху / снизу / изометрия / вписать; вид вписывается в то, что сейчас показано.
- **Взрыв** — ползунок: каждая деталь отъезжает от центра показанного пропорционально расстоянию до него (выпуклые детали при этом не пересекаются), кадр подстраивается.
- **Правка из 3D** работает там, где есть бланк заказа (`NewOrderPage`, `EditOrderPage` передают `onDetailsChange`); в заказе и раскрое — только просмотр (в черновике есть кнопка «✎ Править»). Сохраняется как обычно — кнопкой «Сохранить» заказа. В 3D есть «↶ Отменить».
  - `src/lib/model3dEdit.js` — все расчёты (без three.js): `orderParts`, `editSingles`, `applyEdgeOps`, `findJoints`, `applyJoints`, `clearJoints`, `partGroups`.
  - Строка заказа с количеством — это несколько штук в разных местах модели. Правка идёт по штукам: строка раскладывается, правится, одинаковые штуки снова склеиваются (`editSingles`). Если штуки стали разными (левая и правая боковины) — строка делится. Прямоугольная деталь без обработки симметрична, поэтому её положение (`meta.inst`) приводится к одному из четырёх эквивалентных, чтобы кромка у одинаковых штук записывалась одинаково (`canonFrame`).
  - **Кромка**: «Закромить видимые торцы» — торцы показанных деталей, которые смотрят на зрителя (угол до ~45°) и ничем не заслонены (луч от торца к зрителю); «Снять с видимых»; тап по торцу — поставить/снять (в т. ч. фигурный участок и вырез). Название кромки выбирается в панели.
  - **Присадка**: подсвечиваются стыки «торец к пласти» (`findJoints`, зазор до 0.6 мм). На стык ставится схема из базы фурнитуры (`hardware_presets`, обе части: `face` и `edge`) или одна из встроенных (`BUILTIN_SCHEMES`). В пласти появляется линия разметки по пятну стыка (`layout`, пометка `j3d`) и привязанная к ней присадка; в торце — присадка `kind:'edge'`. Схема, записанная «как для полки», сама поворачивается для стойки. После расстановки отверстия сверяются в 3D (торец ↔ пласть); если не сошлись — пробуется отсчёт с другого конца и другая сторона пары, остаток показывается в сообщении. Деталь, у которой вся глухая присадка оказалась с изнанки, переворачивается (`flipDetail`). Стыки с деталями тоньше 10 мм (задняя стенка) по умолчанию выключены; стыки на фигурных торцах пропускаются.
  - **Править деталь** — редактор контура поверх 3D (паз, вырез, своя присадка); правка применяется при закрытии редактора.
- `mirrorDetail.js`: зеркало присадки теперь зеркалит и шаг парного/дополнительных отверстий, отсчёт вдоль верхнего/нижнего торца и зазор от стойки — раньше при «Отзеркалить» и «Перевернуть деталь» парные отверстия уезжали наружу.
- **Ссылка для клиента**: `migration_model_shares.sql` (таблица `model_shares` + функция `shared_model(token)`, security definer), `src/lib/modelShare.js`, `src/components/ShareLinkBox.jsx`, страница `/view/:token` (`SharedModelPage.jsx`, без входа, только просмотр, с картинками материалов владельца). Ссылка «живая» — показывает сохранённый заказ. Пометки: значок 🔗 на кнопке «3D-модель», плашка в списке заказов, карточка в заказе с кнопками «Скопировать» / «Закрыть доступ» (удаляет строку — ссылка перестаёт работать).

## 3D-просмотр: куб видов, структура модели, перемещение блоков

- **Куб видов** (правый верхний угол 3D): повёрнут так же, как модель (CSS-куб, матрица берётся из камеры каждый кадр); нажатие на грань — вид с этой стороны. Под ним — переключатель «Перспектива / Аксонометрия» (две камеры: `PerspectiveCamera` и `OrthographicCamera`, `setProj` сохраняет вид и масштаб; выбор хранится в `view3d.proj`) и «⌂ Изометрия».
- **Структура** (кнопка «☰ Структура», панель слева): дерево изделие → блоки → детали (`blockTree` в `src/lib/model3dMove.js`). Галочка — отметить блок/деталь (это тот же `sel`, отмеченное синее в модели), ● — показать/скрыть. Вверху — подписи на модели: нет / блоки / детали (режим подписей `block` — одна подпись на изделие).
- **Перемещение** («✥ Двигать», только там, где модель правится — бланк заказа): отмеченное тянется пальцем вдоль одной свободной оси (влево-вправо / вверх-вниз / вперёд-назад), по двум другим закреплено; есть кнопки ±1 / ±10 мм. Упор — вплотную к соседним деталям, зазор 0 (`sweepLimits` / `clampMove`: по габаритам деталей; фигурная деталь считается своим габаритом). Детали, которые уже входят друг в друга, развести можно — обратно не заедут. Вместе с деталями едет фурнитура их блоков (`movingSet`; блок фурнитуры и профилей пишется при импорте из Базиса — `b` в `scene.hardware` / `scene.extras`; у старых заказов и Астры фурнитура привязывается к ближайшей панели).
- «Применить» — `moveModel` сдвигает `meta.inst` (и оси анимации) у деталей заказа и у объектов сохранённой модели; новая модель уходит на страницу через `onSceneChange` (Model3DButton → `setModel3d(packScene(...))`) и сохраняется вместе с заказом кнопкой «Сохранить». «↶ Отменить» возвращает и детали, и модель.

## Кромка: толщина, подрезка, прифуговка → размер в раскрой

- У каждого вида кромки заказа свои настройки: `{ t — толщина, trim — подрезка на толщину, joint — прифуговка, мм }`; ключ — название кромки, `default` — кромка без названия. Хранятся в `orders.edge_types` (jsonb, `migration_edge_types.sql`; пока миграция не выполнена, заказ сохраняется без них с подсказкой) и запоминаются за аккаунтом (`app_settings.edgeTypes`) для новых заказов.
- Формула (`src/lib/edgeCut.js`): с каждой закромленной стороны деталь в раскрое меньше на `(trim ? t : 0) − joint`. Ничего не включено — деталь идёт как записана. Кромка на фигурных участках и в вырезах размер пока не меняет.
- В заказе размеры, контур и присадка всегда «по готовой детали». Заготовку делает `cutDetail(row, types)`: новые `width/length`, пересчитанные контур, вырезы и пазы, пометка `contour.cut = { l, r, b, t }`; её учитывает `getAllDrillPoints` (считает по готовой детали и сдвигает; торцевое отверстие с подрезанной стороны короче на подрезку). Исходная строка — `rawDetail(d)` (`_raw`): править и сохранять нужно её.
- Заготовки берут: NestingPage (`details`; `allDetails` — строки как есть), CncPage, LabelsPage, карты в OrderPage. Бланк заказа, редактор контура и 3D работают с готовой деталью.
- Форма видов кромки — `src/components/EdgeTypes.jsx` (в NewOrderPage и EditOrderPage, вместо прежнего EdgeManager): толщина обязательна; в карточке детали строка «В раскрой с учётом кромки: Д × Ш». При импорте из Базиса толщина подставляется из модели (`typesFromItems`).

- **Свесы кромки**: запас к длине кромки на каждую закромленную сторону (участок). Хранится вместе с видами кромки под служебным ключом `__over` = `{ on, mm }` (`overOf` / `overMm` в `edgeCut.js`); по умолчанию включено, 30 мм, и в этом случае в заказ не пишется. Галочка и величина — в блоке «Виды кромки» бланка; та же галочка — в раскрое рядом с кромкой по типам (`setEdgeOver` сразу пишет в заказ и пересчитывает метраж). `edgeTotals(details, over)`; длина кромки считается по готовой детали (`rawDetail`), а не по заготовке.

## 3D: кромка и крепёж по отмеченным деталям, новый крепёж из 3D

- Отмеченные детали (`sel`) — область работы инструментов: «Закромить видимые» ставит кромку только на их торцы, «Крепёж» показывает стыки только между отмеченными (у одной отмеченной — все её стыки). Ничего не отмечено — вся показанная модель. В панели инструмента — строка «Только отмеченные: N · Все детали». Кнопки-пиктограммы «Кромка» и «Крепёж» стоят справа под кубом видов (со счётчиком отмеченных); они же есть в строке множественного выбора и в меню долгого нажатия. В «Структуре» этих кнопок нет. Ширина панели «Структура» меняется ползунком на её правом крае и запоминается (`view3d.treeW`).
- Кромка в 3D: рядом с названием — толщина (обязательна), «Подрезка», «Прифуговка» — те же настройки вида кромки, что в бланке (`edgeTypes` / `onEdgeTypesChange` через Model3DButton).
- «+ Новый» в панели «Крепёж»: форма нового крепежа (пласть Ø/глубина или сквозное, торец Ø/глубина, отступ от края, зеркально, второе отверстие с шагом) — пишется в ту же базу фурнитуры `hardware_presets` (`saveHardwarePreset`), что и в редакторе контура.

## 3D: правка сохранённого заказа из раскроя и из заказа

- Раньше 3D правилось только из бланка заказа; в раскрое и в заказе был просмотр — значков «Кромка», «Крепёж» и «Двигать» там не было. Теперь `Model3DButton` с `saveToOrder` (NestingPage и OrderPage, пока заказ — черновик) правит сохранённый заказ сам: правки копятся в 3D (`draft`), кнопка «💾 Сохранить изменения в заказ» пишет строки `order_details` (изменённые — update, разделившиеся — insert), настройки кромки и модель, сбрасывает `nesting_result` и перечитывает страницу. При закрытии с несохранёнными правками — вопрос «сохранить?».

## 3D: размер блока и поворот на 90°

- Инструмент «Двигать» (значок ✥ под кубом и кнопка в строке инструментов) теперь с тремя режимами: «Сдвиг», «Размер блока», «Поворот 90°».
- **Размер блока** (`planStretch` + `moveModel` + `stretchModel` в `model3dMove.js`): ширина / высота / глубина отмеченного, новый размер в мм, какой край закреплён. Блок режется плоскостью посередине: всё целиком по подвижную сторону сдвигается; детали, которые плоскость пересекает и которые лежат вдоль оси (полки, дно, задняя стенка), меняют длину (`stretchDetail`: размер детали, `meta.local`, контур, вырезы, пазы, линии разметки; строка заказа с количеством делится по штукам через `editSingles`); панель, у которой вдоль оси толщина, не растягивается. Присадка остаётся привязанной к своим сторонам. Соседние блоки не двигаются.
- **Поворот** (`rotateModel`): отмеченное, а если ничего не отмечено — вся модель, на 90° вокруг X / Y / Z через центр габарита (для моделей, пришедших «лёжа»).
- Общая часть сдвига и поворота — `transformModel` (детали заказа, детали сохранённой модели, профили, фурнитура, оси анимации).

- Клиент: в списке заказов у черновика кнопка «✎ Редактировать», в раскрое в шапке — «✎ Править заказ» (обе ведут в бланк `/orders/:id/edit`).
- Производство: в заявке кнопка «↩ Вернуть на доработку» (кроме исполненных) — спрашивает причину и вызывает `production_return_order(p_order, p_note)` (`migration_return_order.sql`: колонки `orders.return_note`, `orders.returned_at` и функция security definer). Заказ снова становится черновиком и уходит из заявок производства; клиент видит плашку «Производство вернуло заказ на доработку: …» в списке заказов и в раскрое, правит заказ и оформляет заново.

## Деловые обрезки: производство, G-код, бирки

- Обрезки, отмеченные в раскрое вручную, лежат в листе (`sheet.manualOffcuts`: `{ x, y, w, h }`, Y — от низа рабочей зоны, у края листа обрезок продлён на отступ) и сохраняются вместе с раскроем в `nesting_result`. Теперь их рисует `SheetsOverview` (карты в заказе — их видит производство): оранжевый пунктир и размер длина×ширина.
- G-код (`buildSheetGcode`): обрезок отрезается фрезой контура детали, снаружи, после всех деталей. Стороны на краю листа пропускаются; оставшиеся идут незамкнутыми цепочками (`cutOpen`, проходы туда-обратно, концы прижаты к краю листа); обрезок внутри листа обходится по периметру (`cutLoop`).
- Бирки: галочка «Печатать бирки на обрезки» (`tpl.offcuts`) — после бирок деталей листа идут простые бирки обрезков (`drawOffcutLabel`: заказ, материал, размер, номер листа); попадают в печать, в PDF и в файлы маркировочного стола. Порядок — общий с деталями (`labelSeq(sheet, geo, mode, tpl)`: детали и обрезки одним обходом; `labelOrder` — только детали). Точка наклейки на обрезок — `offcutPoint`: угол обрезка и отступы от его сторон из `tpl.offcut = { corner, dx, dy }` (по умолчанию левый нижний, 100 × 100 мм; обрезок уже двух отступов — по середине).
- Метраж кромки в раскрое и в заказе показывается с сотыми.

## Сохранение файлов ЧПУ и бирок: папки, латиница, «Поделиться»

- `SaveFilesDialog` принимает `folders = [заказ, материал]`: при сохранении по отдельности (где есть выбор папки) внутри выбранной папки создаются вложенные папки, в архиве файлы лежат в них же. На телефоне браузер папки создавать не умеет — там по отдельности файлы идут в «Загрузки», папки есть только в архиве.
- Имена программ, файлов бирок и папок — строго латиницей (`toLatin` + только `A–Z a–z 0–9 _ . -`), включая название материала.
- Кнопка «Отправить в приложение (Яндекс Диск и др.)» — системное «Поделиться» с архивом; показывается, только если браузер умеет передавать такой файл (`navigator.canShare`). Список мест в обычном окне сохранения задаёт телефон, приложение на него не влияет.

## Пользователи и регистрация по запросу (администратор)

- `migration_users_admin.sql`: таблицы `app_config` (`signup_open`) и `signup_requests` (заявки по номеру телефона), функции `signup_open`, `request_signup` (для экрана входа) и `admin_users`, `admin_requests`, `admin_set_signup`, `admin_set_request`, `admin_allow_phone`, `admin_set_role` (только для `profiles.role = 'admin'`, проверка внутри функций). Триггер `check_signup_allowed` на `auth.users`: при закрытой регистрации нового пользователя можно создать только по одобренной заявке (номера «8 701…» и «+7 701…» считаются одним).
- `src/lib/adminApi.js`, страница `/users` (`UsersPage.jsx`, вход — карточка «Пользователи и регистрация» в профиле администратора): переключатель «регистрация открыта / только по запросу», заявки (одобрить, отклонить, разрешить номер без заявки), список зарегистрированных (имя, телефон, WhatsApp, роль, дата регистрации, последний вход, число заказов), смена роли.
- `AuthPage.jsx`: если регистрация закрыта, вместо «Регистрация» — «Заявка» (имя, телефон, комментарий); когда номер одобрен, по той же кнопке открывается обычная регистрация с паролем. Пока миграция не выполнена, всё работает как раньше (регистрация открыта).
- `migration_profiles_protect.sql`: триггер `protect_profiles` на `profiles` — роль меняет только администратор (или SQL Editor), обычный пользователь правит только свой профиль, новый профиль всегда «клиент». Работает независимо от политик таблицы.
- `migration_access_lockdown.sql`: защита строк (RLS) на `profiles`, `orders`, `order_details`, `order_models`, `model_shares`, `productions` — прежние политики снимаются, новые: каждый видит и меняет только своё, всё чужое — только администратор (оператор чужих заказов не видит). Номер нового заказа выдаёт функция `next_order_number` (номера уникальны среди всех пользователей). `migration_security_all.sql` — все четыре миграции безопасности одним файлом.

## Кабинет производства, водяной знак

- `migration_production_cabinet.sql` (входит в `migration_security_all.sql`): у `productions` — `owner_id`, `phone`, `city`; функции `register_production` (своё производство; роль клиента становится `operator` = «Производство»), `production_orders` (заявки моего производства с заказчиком), `order_client`, `production_set_status`; обновлённая `admin_users` со статистикой. Права: производство ВИДИТ оформленные на него заказы, детали и 3D, менять может только статус (через функцию); детали и модель меняет только хозяин заказа и администратор; триггер `protect_order_status` не даёт заказчику самому поставить «принят / исполнен».
- `src/lib/productionApi.js`, `src/components/ProductionForm.jsx`, страница `/production` (`ProductionPage.jsx`, пункт «Производство» в нижнем меню у всех): нет производства — форма регистрации; есть — карточка производства, счётчики, параметры станка (рез, отступы), заявки с фильтром «Новые / В работе / Исполнены / Все» и кнопками «Принять», «Обсудить», «Исполнен».
- «Оформить» в раскрое (`NestingPage.submitOrder`): если производство не выбрано — у кого есть своё, заказ уходит на него; остальным окно «На какое производство оформить?»: выбрать из списка или зарегистрировать своё. Пока миграция не выполнена — оформляется как раньше.
- Статусы для заказчика: `new` — «Отправлен, ждёт ответа», `inwork` — «Принят в работу».
- Страница «Пользователи»: фильтр «Все / Клиенты / Производства»; у производства — заявок получено / принято / исполнено; у каждого — заказов создано / оформлено.
- `src/components/Watermark.jsx` — водяной знак поверх всего приложения (телефон и имя вошедшего), у администратора его нет. Запретить или отследить снимок экрана из браузера нельзя.
- Производства и закрытая регистрация: `productions.status` (`pending` → `approved` / `rejected`) и обязательная `country`. Пока регистрация закрыта («только по запросу»), новое производство создаётся как `pending`: его видят только владелец и администратор, заявки на него не идут, роль владельца остаётся «клиент». Администратор подтверждает или отклоняет на странице «Пользователи» (`admin_set_production`). Регистрация открыта — производство подтверждается сразу. Отклонённую заявку владелец может подать заново.
- Короткая ссылка на 3D-модель: `migration_share_code.sql` — `model_shares.code` (8 знаков), функция `shared_model_code`, маршрут `/v/:code` (старые `/view/:token` работают). Клиенту по ссылке название приложения не показывается: заголовок страницы в `index.html` нейтральный («3D-модель»), «РаскройPro» ставится в `main.jsx` только для остальных страниц.

## Кабинет производства и ЧПУ (октябрь 2026)
- **OrderPage**: карточка «Материал», принятые карты раскроя (SheetsOverview) НАД списком деталей; для производства — кнопки «Открыть / перекроить», «ЧПУ», «Бирки». Те же «ЧПУ» и «Бирки» — в NestingPage у оформленного заказа (вместо «Оформить»).
- Производство может перекроить чужой оформленный заказ: раскрой пишется функцией базы `production_save_nesting` (migration_production_nesting.sql).
- `src/lib/savedNesting.js` — сохранённый раскрой по материалам (`savedNestings`, `sheetGeo`).
- **ЧПУ** (`/orders/:id/cnc`, CncPage.jsx): вкладки Листы / Обработка / Инструменты / Основные / Команды.
  - `src/lib/cncSettings.js` — настройки за аккаунтом (`user_metadata.app_settings.cnc`): постпроцессоры (поле, начало, высота безопасности, заглубления, команды с {T} и {S}), база инструментов (фреза / сверло), обработка контуров (инструмент, направление, вход под наклоном / прямо; слои выемок и отверстий).
  - `src/lib/gcode.js` — генератор: X — ширина листа, Y — длина, Z0 — жертвенный стол. Отверстия → пазы → выемки → вырезы → контуры (мелкие первыми). Контур: эквидистанта на радиус фрезы (`offsetLoop`), вход по контуру под углом, разгон и торможение подачи ступенями. Паз / выемка (`rectPaths`): проходы вдоль длинной стороны с шагом и припуском 2 мм, последний — периметр по часовой; сторона на краю детали — центр фрезы выходит на линию. Дуги выводятся отрезками G1.
  - Не обрабатываются (выдаётся предупреждение): отверстия в торец, обработка с изнанки, выемки не прямоугольной формы.
  - `src/lib/gcodeSim.js` + `components/GcodeSimulator.jsx` — симулятор (G0–G3), вид сверху, время по подачам.
- **Бирки** (`/orders/:id/labels`, LabelsPage.jsx) — первая версия: бирки по листам, печать.
- **Контур детали (доработка):** обход начинается и заканчивается в углу (за угол не заходит, отрезки дважды не режутся); вход под наклоном — по первому отрезку к углу (`cutLoop`). Начало — в углу со стороны середины листа, последним режется отрезок, обращённый внутрь листа (`orientFromInside`). Мелкие детали (`ops.outer.smallArea`, м²) режутся первыми, от края листа внутрь. Несколько проходов (`passes`, `sideAllow`, `leftover`, `smallOnly`): первые — с припуском на основной подаче, последний — начисто по настройкам фрезы.
- **Симулятор — 3D** (three.js, подгружается лениво): вращение, слои траекторий (контуры, вырезы, пазы и выемки, отверстия, входы и выходы, холостые) включаются отдельно; генератор отдаёт `kinds` / `opIds` по строкам. Тап по траектории или строке кода — выделение; список G-кода листается.
- Файлы УП сохраняются отдельными файлами (без zip): папка через showDirectoryPicker, иначе загрузки по одному.
- **Симулятор (доработка):** после «Пуск» траектории строятся по ходу фрезы (до пуска видна вся программа); лист «слоёный» — рез виден объёмно (насквозь до стола, паз до середины); модель шпинделя; граница между 3D-окном и списком кода двигается. **Порядок контуров:** начало всегда с детали у края листа; мелкие — рядами от края внутрь; остальные — кратчайший маршрут (ближайший сосед + 2-opt, `shortenTravel`). Начало контура — угол детали, ближайший к центру листа.
- **Ссылка на симуляцию** (`/s/код`, SharedSimPage.jsx, без входа): кнопка «🔗 Ссылка» в симуляторе. `src/lib/simShare.js` + таблица `sim_shares` и функция `shared_sim` (migration_sim_shares.sql). Ссылка — снимок программы листа (G-код, лист, контуры, диаметры инструментов); одна на лист, повторное создание обновляет снимок; «Закрыть доступ» удаляет.
- **ЧПУ, память и «назад»:** какие листы были созданы — помнится на устройстве (`localStorage cnc:<user>:<order>`), при возвращении программы создаются заново автоматически. Открытый симулятор — в адресе (`?sim=<лист>`), поэтому системная кнопка «назад» закрывает симулятор так же, как «×». **Открытые ссылки на симуляцию** видны всегда: `SimLinksBox` в заказе и в ЧПУ (копировать / закрыть), метка в списках заказов и заявок.
